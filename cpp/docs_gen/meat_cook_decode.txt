# Meat / fish cooking decode (Mini DAYZ 1.4.1)

Source: `original_docs/data.js` → function `item_activate` (see also `functions/item_activate_decoded.txt`).
Object type index **253** = fireplace (`images/fireplace-sheet*.png`, anims `on` / `off`).

## Verdict

Cooking is **not** an inventory `Cook_*` recipe and **not** in-place `SetInstanceVar` item-id swap.
It is **`item_activate` on raw food** while overlapping a **lit fireplace (253, IV0==1)**:
play **`meat_cook`**, wait **5s**, consume raw (`SetReturnValue -1`), then
`CallFunction Check_space_inventory(-1, <cooked_id>)`.

**No C++ cook port from this pass** — no direct `Spawn_drop` / item-id `SetInstanceVar` on the cook success branch
(only `Check_space_inventory(-1, N)`; `Spawn_drop_from_player` appears only on the clothing-full
`Check_space_backpack` `CompareParam 0 == -1` overflow path).

## Verified — raw → cooked conversions (`item_activate`)

Shared success sequence (all six raws):

1. `SetReturnValue -1` (consume activated raw)
2. `PlayByName "meat_cook"`
3. `IV21=1` → `Wait 5` → `IV21=0`
4. `CallFunction "Check_space_inventory" (-1, <cooked_id>)`
5. client_log success code **56** (green)

| Raw id | Name (items_eng) | Cooked id | Name |
|--------|------------------|-----------|------|
| **60** | Raw steak | **61** | Cooked steak |
| **71** | Rabbit meat | **72** | Cooked rabbit meat |
| **91** | Herring | **95** | Small fish fillet |
| **92** | Salmon | **96** | Big fish fillet |
| **93** | Ruffe | **95** | Small fish fillet |
| **94** | Perch | **96** | Big fish fillet |

Fish mapping verified: herring/ruffe → **95**; salmon/perch → **96**.

### `Check_space_inventory(-1, cooked_id)` (give cooked)

- Primary `OnFunction Check_space_inventory` body: writes bag arrays with **param1=item id**, **param2** qty/slot arg; `Items_update`; pick SFX; `Destroy` UID from **param0** ( **-1** = no ground sprite).
- If bag/clothing cascade fills: `Check_space_backpack` has `CompareParam 0 == -1` → **`Spawn_drop_from_player`(param1, param2)** (ground drop overflow).
- **Not** a craft-tree `Spawn_drop` with recipe name.
- **Not** `SetInstanceVar` changing the same instance from 60→61.
